## What GeDefense is

GeDefense Mobile is a native Android security platform that combines a local VPN enforcement plane, endpoint telemetry, XDR/EDR correlation, threat intelligence, app-risk analysis, encrypted evidence storage and optional Android Device Owner controls.

The architecture is intentionally **local-first**: security decisions are made on the device. GeDefense does not require a VGT cloud account and does not upload packet payloads, package inventories, scan artifacts or XDR evidence to a VGT backend. Optional threat/ASN data updates are downloaded as bounded, validated data inputs; they do not turn the product into a cloud verdict service.

### Core capabilities

| Area | Capability |
| --- | --- |
| Network protection | Full Flow `VpnService`, direct L4 egress, selective routing and WireGuard L3 transport |
| Threat intelligence | Local compiled threat policy with deterministic feed authority and offline lookups |
| Telemetry Shield | Local filtering of known advertising, analytics and optional device-telemetry endpoints without TLS interception |
| Encrypted DNS control | DoT/DoQ controls in strict profiles, without installing a MITM root CA |
| EDR / XDR | Package, behavior, network, integrity and device-hardening evidence correlated locally |
| InstallGuard | Pre-egress flow gate plus bounded Fast/Deep app scanning for newly installed packages |
| Malware analysis | Local app/package and bounded shared-storage inspection |
| Secure Telemetry Vault | Domain-separated AES-256-GCM storage with authenticated snapshots and update-stable key custody |
| Evidence | Encrypted, authenticated local evidence ledger with bounded recovery semantics |
| Resilience | Bounded recovery supervisor, health checks and fail-closed degradation behavior |
| TITAN | Optional Device Owner policy plane for managed-device hardening and lockdown controls |
| Diagnostics | User-initiated aggregate-only support bundle; no automatic upload |

## Why the privacy model matters

Many mobile security products improve visibility by sending telemetry to central infrastructure. GeDefense is designed around the opposite default: **analyse locally first, keep evidence local, export only when the user explicitly chooses to do so**.

The **Telemetry Shield** also protects against telemetry generated by other applications where it can be identified at the network/policy layer. It deliberately does **not** perform TLS interception. If an application mixes functional traffic and telemetry inside the same encrypted first-party endpoint, GeDefense will not pretend that network metadata can magically separate the two.

See [`PRIVACY.md`](PRIVACY.md), [`NETWORK-EGRESS.md`](NETWORK-EGRESS.md) and [`SECURE-TELEMETRY-VAULT.md`](SECURE-TELEMETRY-VAULT.md).

## Architecture at a glance

```text
Android UI / Control Plane (Kotlin)
        |
        | authenticated Unix-domain control channel
        | SCM_RIGHTS descriptor transfer
        v
GaiaNet V2 Data Plane (Go, separate process)
        |
        +-- Threat policy / Telemetry Shield / Package gate
        +-- Direct L4 transport
        `-- WireGuard L3 transport
                |
                v
          Physical network
```

The Android host owns lifecycle, policy, Keystore access and UI state. GaiaNet is executed as a separate process from the APK native-library directory and receives only the bounded file descriptors/configuration required for the active transport path. It is not loaded through JNI in the packet hot path.

The current toolchain is pinned to **Go 1.26.8**, Kotlin 1.9.24, Gradle 8.7, JDK 17, Android API 36 and NDK r27c. See [`TOOLCHAINS.lock`](TOOLCHAINS.lock) and [`SUPPLY-CHAIN.md`](SUPPLY-CHAIN.md).

## Security model

GeDefense is built around a few non-negotiable invariants:

- fail closed for security-critical integrity, VPN and evidence failures;
- no TLS interception by default;
- no dynamic code loading or WebView-based security plane;
- bounded queues, parsing, scanning, retries and background work;
- no whole-UID WireGuard bypass: only exact upstream transport sockets are protected/bound;
- independent key domains for persisted security state;
- update-stable encryption custody that is not derived from APK hashes or version numbers;
- crash-safe authenticated state publication (`stage -> fsync -> verify -> atomic replace -> directory fsync`);
- explicit trust boundaries between Android host, GaiaNet, external datasets and Android platform services.

Read [`SECURITY.md`](SECURITY.md), [`THREAT-MODEL.md`](THREAT-MODEL.md), [`ARCHITECTURE.md`](ARCHITECTURE.md) and [`SUPPLY-CHAIN.md`](SUPPLY-CHAIN.md) before deploying GeDefense in a sensitive environment.

## Protection modes

GeDefense supports multiple operating profiles so users can trade blast radius, compatibility and enforcement strength deliberately.

- **Selective**: routes only policy-selected threat prefixes into the protection plane.
- **Full Flow / Direct**: processes device traffic through GaiaNet and emits approved traffic through direct kernel sockets.
- **WireGuard**: routes Full Flow traffic through the embedded `wireguard-go` L3 transport.
- **Strict / Lockdown**: designed to cooperate with Android Always-on VPN / lockdown semantics and fail closed when the secure transport is unavailable.

## Building

### Required toolchain

- JDK 17
- Gradle 8.7
- Android SDK Platform 36
- Android Build Tools 36.0.0
- Android NDK `27.2.12479018` (r27c)
- Go 1.26.8

The Android application has **zero third-party runtime libraries** in `:app`/`:core`. GaiaNet uses a small, pinned, vendored Go dependency set including `wireguard-go` and selected `golang.org/x/*` modules.

Run the complete release-readiness gate:

```bash
bash tools/release-readiness.sh
```

For the exact offline/reproducible build procedure, see [`BUILD-RUNBOOK.md`](BUILD-RUNBOOK.md).

## Verification and release gates

The repository includes machine-verifiable gates for, among other things:

- Core logic and crypto/store regression tests;
- Go tests, race tests and Android-helper tagged tests;
- WireGuard protocol/source invariants;
- main-thread / startup ANR boundaries;
- vault migration and continuity rules;
- Privacy Shield and onboarding behavior;
- InstallGuard and resilience invariants;
- ASN evidence provenance;
- source-manifest verification;
- 16 KiB ELF `PT_LOAD` alignment;
- deterministic CycloneDX SBOM validation;
- release artifact metadata/signature checks;
- lint with a zero-warning release policy.

See [`RELEASE-CHECKLIST.md`](RELEASE-CHECKLIST.md) and [`BETA-TEST-PLAN.md`](BETA-TEST-PLAN.md) for the remaining real-device acceptance work.

## Security reporting

Please do **not** disclose exploitable vulnerabilities or sensitive device evidence in public issues.

**Security contact:** [security@visiongaia.de](mailto:security@visiongaia.de)

Use GitHub private vulnerability reporting when available. Include the affected GeDefense version, Android/OEM version, protection mode, sanitized reproduction steps and whether the device is rooted or uses a custom ROM.
